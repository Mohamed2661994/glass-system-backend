# Public Products and Stock Webhook Plan

## Goal

Implement webhook-based invalidation for the public DC projections currently exposed through:

- `GET /public/products`
- `GET /public/stock`

The implementation must not break, slow down, or couple itself to the current sales, purchase, return, transfer, or DB sync flows.

## Public Projection Scope

### `/public/products` currently returns

- `product_code` from `products.id`
- `name`
- `wholesale_price`
- `retail_price`
- `discount_amount`
- `barcode`
- active products only via `WHERE is_active = true`

### `/public/stock` currently returns

- product-level fields from `products`
- aggregated stock from `stock`
- warehouse-scoped stock breakdown using `warehouses`
- variant data from `product_variants`
- active products only via `WHERE is_active = true`
- optional branch filtering using `warehouses.branch_id`

Only changes that alter either of these public projections should emit webhook events.

## Current Implementation Status

- Backend code for the public webhook pipeline has been implemented.
- All new behavior is feature-flagged and remains inactive until explicitly enabled.
- Admin test, replay, and status routes were added for controlled dry runs.
- Syntax validation passed for the modified backend files.
- Deployment, environment setup, and end-to-end validation are still pending.

## Zero-Impact Guardrails

- Do not make invoice, purchase, return, transfer, or sync success depend on webhook delivery.
- Do not change any existing API response contracts.
- Do not send webhooks directly from route handlers.
- Do not send webhooks directly from DB triggers.
- Keep all new behavior behind feature flags.
- Start with capture-only mode before enabling delivery.
- Prefer additive schema changes only.
- Keep webhook infrastructure separate from the existing DB failover and pool-sync logic.
- Keep trigger logic lightweight: insert a log row only, then exit.
- Do not fan out large product lists inside hot transaction paths.
- For broad low-frequency admin changes, allow coarse invalidation events instead of per-product expansion.

## Final Webhook Contract for the Website Team

### Delivery Model

- One HTTP `POST` request carries one event type.
- Supported event types:
  - `public.products.changed`
  - `public.stock.changed`
- Each request may batch multiple changed items in a single `items` array.
- The same backend transaction may produce two webhook requests if it changes both public projections.

### HTTP Request

- Method: `POST`
- Content-Type: `application/json`
- Timeout: 3000 ms recommended default
- Authentication: HMAC SHA-256 using a shared secret

### Request Headers

- `X-Glass-Event-Id`: unique event ID
- `X-Glass-Event-Type`: event type
- `X-Glass-Timestamp`: ISO timestamp used in the signature
- `X-Glass-Signature`: `sha256=<hex_hmac>`

### Signature Formula

- Signature input: `<timestamp>.<raw_request_body>`
- Algorithm: HMAC SHA-256
- Encoding: lowercase hex digest

Example:

```text
X-Glass-Signature: sha256=4fa3c7...
```

### Receiver Success Contract

- Any `2xx` response means the event was accepted.
- Suggested success body:

```json
{
  "received": true
}
```

- Non-`2xx`, timeout, or network failure should trigger retry by the DC backend.

### Idempotency Rule

- The website side should deduplicate by `eventId`.
- `revision` should be treated as monotonic and safe for ordering/debugging.
- Retried deliveries may resend the same `eventId` and same payload.

### Common Event Body

```json
{
  "eventId": "evt_public_stock_000123",
  "eventType": "public.stock.changed",
  "changedAt": "2026-05-18T12:00:00.000Z",
  "revision": 123,
  "source": "glass-system-backend",
  "scope": {
    "mode": "items"
  },
  "items": []
}
```

### Common Top-Level Fields

- `eventId`: unique and stable across retries
- `eventType`: one of the supported event names
- `changedAt`: event creation timestamp in ISO format
- `revision`: monotonic sequence generated by the delivery queue
- `source`: fixed producer name, for example `glass-system-backend`
- `scope.mode`: one of `items`, `branch`, or `full`
- `items`: batched affected items, may be empty for coarse invalidation events

### `public.products.changed` Item Shape

```json
{
  "productId": 123,
  "productCode": 123,
  "barcode": "6222000001111",
  "operation": "upsert",
  "changedFields": ["name", "retail_price", "is_active"]
}
```

Rules:

- `productId` is the canonical internal ID.
- `productCode` mirrors the current public API naming for compatibility.
- `operation` is `upsert` or `delete`.
- `changedFields` includes only public projection fields when known.

### `public.stock.changed` Item Shape

```json
{
  "productId": 123,
  "productCode": 123,
  "variantId": 7,
  "barcode": "6222000001111",
  "warehouseId": 2,
  "branchId": 1,
  "operation": "upsert",
  "oldStock": 10,
  "newStock": 8,
  "changedFields": ["quantity"]
}
```

Rules:

- `productId + variantId + warehouseId` is the stable stock identity.
- `branchId` is included because `/public/stock` supports branch filtering.
- `oldStock` and `newStock` are expected for quantity-driven changes when available.
- For metadata-only stock invalidation, `oldStock` and `newStock` may be `null`.

### Coarse Invalidation Support

To avoid expensive fan-out during rare broad admin changes, the contract also supports coarse invalidation.

Example:

```json
{
  "eventId": "evt_public_stock_000124",
  "eventType": "public.stock.changed",
  "changedAt": "2026-05-18T12:05:00.000Z",
  "revision": 124,
  "source": "glass-system-backend",
  "scope": {
    "mode": "full"
  },
  "items": []
}
```

Meaning:

- `scope.mode = items`: invalidate only listed items
- `scope.mode = branch`: invalidate stock caches for listed branches only
- `scope.mode = full`: invalidate the whole public projection for that event type

## Recommended Storage Design

### Change Log Table

Recommended table: `public_webhook_change_log`

Suggested columns:

- `id BIGSERIAL PRIMARY KEY`
- `batch_txid BIGINT NOT NULL`
- `event_type TEXT NOT NULL`
- `scope_mode TEXT NOT NULL DEFAULT 'items'`
- `product_id BIGINT NULL`
- `variant_id BIGINT NULL`
- `warehouse_id BIGINT NULL`
- `branch_id BIGINT NULL`
- `operation TEXT NOT NULL DEFAULT 'upsert'`
- `changed_fields JSONB NOT NULL DEFAULT '[]'::jsonb`
- `old_stock NUMERIC NULL`
- `new_stock NUMERIC NULL`
- `created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`

Notes:

- Append-only.
- No business flow should depend on reading from this table.
- Trigger writes should stop at one lightweight insert.

### Delivery Queue Table

Recommended table: `public_webhook_deliveries`

Suggested columns:

- `id BIGSERIAL PRIMARY KEY`
- `batch_txid BIGINT NOT NULL`
- `event_type TEXT NOT NULL`
- `event_id TEXT NOT NULL`
- `revision BIGINT NOT NULL`
- `status TEXT NOT NULL DEFAULT 'pending'`
- `attempts INTEGER NOT NULL DEFAULT 0`
- `next_attempt_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`
- `last_error TEXT NULL`
- `delivered_at TIMESTAMPTZ NULL`

Notes:

- One delivery row per `batch_txid + event_type`.
- `revision` can be derived from the queue row ID.
- The worker builds the HTTP payload from the change log only after commit.

## Trigger Matrix

Only endpoint-visible changes should emit events.

| Source table           | Change condition                                                                                 | Emit event                                           | Scope   | Item payload expectation                                 | Safety note                                             |
| ---------------------- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------- | ------- | -------------------------------------------------------- | ------------------------------------------------------- |
| `products`             | `INSERT` where `is_active = true`                                                                | `public.products.changed` and `public.stock.changed` | `items` | one item for the product                                 | cheap single-row log insert only                        |
| `products`             | `UPDATE` of `name`, `wholesale_price`, `retail_price`, `discount_amount`, `barcode`, `is_active` | `public.products.changed` and `public.stock.changed` | `items` | one item with `changedFields`                            | fire only if an endpoint-visible field actually changed |
| `products`             | `UPDATE` of `manufacturer`, `wholesale_package`, `retail_package`, `description`                 | `public.stock.changed`                               | `items` | one item with `changedFields`                            | no `public.products.changed` needed                     |
| `products`             | hard `DELETE` of an active product                                                               | `public.products.changed` and `public.stock.changed` | `items` | one item with `operation = delete`                       | if hard delete is ever used                             |
| `products`             | update of non-public fields only                                                                 | none                                                 | none    | none                                                     | skip to avoid noise                                     |
| `product_variants`     | `INSERT`                                                                                         | `public.stock.changed`                               | `items` | one variant item                                         | `/public/stock` exposes variants                        |
| `product_variants`     | `UPDATE` of `label`, `barcode`, `retail_price`, `wholesale_price`                                | `public.stock.changed`                               | `items` | one variant item with `changedFields`                    | only visible fields should trigger                      |
| `product_variants`     | `DELETE`                                                                                         | `public.stock.changed`                               | `items` | one variant item with `operation = delete`               | variant removed from public stock payload               |
| `product_variants`     | update of non-public fields only                                                                 | none                                                 | none    | none                                                     | skip to avoid noise                                     |
| `stock`                | `INSERT`                                                                                         | `public.stock.changed`                               | `items` | include `oldStock = 0`, `newStock`                       | source of truth for quantity changes                    |
| `stock`                | `UPDATE OF quantity` where quantity actually changed                                             | `public.stock.changed`                               | `items` | include `oldStock` and `newStock`                        | do not watch `stock_movements` directly                 |
| `stock`                | `DELETE`                                                                                         | `public.stock.changed`                               | `items` | include `oldStock`, `newStock = 0`, `operation = delete` | delete is projection-affecting                          |
| `warehouses`           | `UPDATE` of `name`                                                                               | `public.stock.changed`                               | `full`  | no items required                                        | avoid fan-out across all stocked products               |
| `warehouses`           | `UPDATE` of `branch_id`                                                                          | `public.stock.changed`                               | `full`  | no items required                                        | safer than per-product expansion                        |
| `warehouses`           | `INSERT` or `DELETE` affecting public stock visibility                                           | `public.stock.changed`                               | `full`  | no items required                                        | rare admin event                                        |
| `stock_movements`      | any change                                                                                       | none directly                                        | none    | none                                                     | stock event must come from `stock` only                 |
| `invoices`             | any change                                                                                       | none directly                                        | none    | none                                                     | invoice flow must stay untouched                        |
| `invoice_items`        | any change                                                                                       | none directly                                        | none    | none                                                     | public stock invalidation should follow `stock` result  |
| `cash_in` / `cash_out` | any change                                                                                       | none                                                 | none    | none                                                     | not part of public projections                          |
